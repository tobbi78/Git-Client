Überblick

Git-Client ist eine macOS-App zum Betrachten und Verwalten von Git-Repositories — ähnlich wie Sourcetree. Beim Start öffnet sich die Repository-Übersicht (Bookmark-Browser). Öffnest du ein Repository, wechselt die App in die Commit-Ansicht mit Graph, Seitenleiste und Diff-Bereich.

BereichInhalt
Seitenleiste (links)Branches, Remote-Branches, Tags
Commit-Liste (rechts oben)Graph + Commit-Zeilen, Suche/Filter
Diff (rechts unten)Geänderter Code des ausgewählten Commits

Befehlspalette (⌘K)

Mit ⌘K öffnest du jederzeit eine Spotlight-artige Befehlspalette. Sie durchsucht immer alle Repository-Bookmarks (zum Öffnen/Wechseln) und — sobald ein Repository geöffnet ist — zusätzlich dessen bereits geladene Branches, Tags und Commits.

  • Tippen filtert die Trefferliste (Teilstring, unabhängig von Groß-/Kleinschreibung).
  • ↑/↓ bewegen die Auswahl, ⏎ oder ein Klick öffnet das Repository bzw. springt zum Branch/Tag/Commit.
  • Esc oder ein Klick außerhalb schließt die Palette.

Repositories verwalten

Bookmark-Browser

Der Bookmark-Browser zeigt eine Baumstruktur aus Ordnern und Repository-Verknüpfungen (Bookmarks). Er öffnet sich automatisch beim Start, solange kein Repository geöffnet ist.

Repository hinzufügen

Klicke auf „Repository hinzufügen" in der Toolbar und wähle einen Ordner, der ein Git-Repository enthält (d.h. einen Ordner mit einem versteckten .git-Unterordner).

Repository klonen

Mit „Klonen" in der Toolbar kannst du ein Remote-Repository herunterladen. Gib die HTTPS-URL sowie einen lokalen Zielordner an. Für private Repositories kannst du optional Benutzername und Passwort/Token eingeben — diese werden sicher im macOS Keychain gespeichert, nie in einer Datei.

Ordner anlegen

Mit „Neuer Ordner" kannst du Repositories thematisch gruppieren (z.B. „Arbeit", „Privat", „Open Source").

Repository öffnen

Doppelklick auf einen Repository-Eintrag öffnet das Repository in der Commit-Ansicht. Klicke auf „Zurück" in der Toolbar (Pfeil-Symbol), um zur Übersicht zurückzukehren.

Status pro Repository

Jeder Repository-Eintrag zeigt direkt in der Übersicht eine kompakte Statuszeile — ganz ohne das Repository zu öffnen:

AnzeigeBedeutung
Branch-Symbol + NameAktuell ausgecheckter Branch
↓ mit ZahlSo viele Commits liegen auf dem Server, die lokal noch fehlen
↑ mit ZahlSo viele lokale Commits sind noch nicht gepusht
Stift-SymbolEs gibt unkommittete Änderungen im Arbeitsverzeichnis
Datum rechtsbündigZeitpunkt des letzten Commits, relativ (z.B. „vor 3 Std.")

Ein orangenes Warnsymbol ⚠️ statt der Statuszeile bedeutet, dass der Repository-Ordner unter dem gespeicherten Pfad nicht mehr gefunden wird (siehe unten).

Umsortieren per Drag & Drop

Repositories und Ordner können per Drag & Drop in der Baumstruktur verschoben werden — sowohl auf derselben Ebene als auch in einen anderen Ordner hinein.

Kontextmenü (Rechtsklick)

  • Umbenennen — Namen eines Ordners oder Bookmarks ändern.
  • In Ordner verschieben — Eintrag in einen anderen Ordner bewegen.
  • Im Terminal öffnen — öffnet den Repository-Ordner in der Terminal-App. Steht auch als Toolbar-Button im geöffneten Repository zur Verfügung.
  • Pfad aktualisieren — erscheint, wenn das Repository an seinem gespeicherten Pfad nicht mehr vorhanden ist (Warnsymbol ⚠️). Wähle den neuen Speicherort.
  • Entfernen — löscht den Eintrag aus der Übersicht (das Repository auf der Festplatte bleibt unberührt).
Hinweis: Ein Warnsymbol ⚠️ neben einem Eintrag bedeutet, dass der hinterlegte Pfad nicht mehr existiert. Nutze „Pfad aktualisieren", um das Repository am neuen Ort zu verknüpfen.

Wo werden die Repositories gespeichert?

Die App speichert ausschließlich Verknüpfungen auf bestehende lokale Repositories — keine Kopien der Daten selbst. Die Liste der Verknüpfungen liegt in: 

~/Library/Application Support/Git-Client/bookmarks.json

Passwörter und Tokens werden niemals in dieser Datei abgelegt, sondern ausschließlich im macOS Keychain.

Commit-History & Graph lesen

Nach dem Öffnen eines Repositories siehst du die Commit-Historie (git log --all) in umgekehrter chronologischer Reihenfolge — der neueste Commit steht oben.

Spalten der Commit-Liste

SpalteBedeutung
GraphFarbige Linien und Knoten zeigen den Branching/Merge-Verlauf
BetreffErste Zeile der Commit-Nachricht
Kurz-SHAAbgekürzter Commit-Hash (8 Zeichen)
AutorName des Commit-Autors
DatumDatum und Uhrzeit des Commits

Den Graph lesen

  • Jede farbige Linie (Lane) entspricht einem Branch-Verlauf.
  • Ein ausgefüllter Kreis auf einer Lane markiert den Commit selbst.
  • Linien, die sich aufteilen, zeigen einen neuen Branch-Abzweig.
  • Linien, die sich zusammenführen, stellen einen Merge dar.

Ref-Badges

Direkt über der Commit-Nachricht erscheinen farbige Badges für bekannte Referenzen:

FarbeBedeutung
OrangeHEAD — aktueller Checkout-Stand
BlauLokaler Branch
GrünRemote-Branch (z.B. origin/main)
LilaTag

Commit auswählen

Klicke auf eine Zeile, um den Commit auszuwählen. Im unteren Bereich erscheint automatisch der Diff dieses Commits.

Ein Rechtsklick auf eine Commit-Zeile bietet „SHA kopieren" und „Commit-Nachricht kopieren" an.

Große Repositories: Lazy Loading

Bei Repositories mit vielen Commits lädt die App zunächst nur die neuesten 2.000 Commits (Standardwert). Sobald du ans Ende der Liste scrollst, werden automatisch weitere Commits nachgeladen — so lange, bis die vollständige Historie angezeigt wird.

Tipp: Die Anzahl der initial geladenen Commits lässt sich in den Einstellungen (⌘,) anpassen.

Commits durchsuchen & filtern

Oberhalb der Commit-Liste befindet sich ein Suchfeld, mit dem sich die Historie nach Nachricht durchsuchen lässt. Die Eingabe wird entprellt (300 ms), sodass die Suche auch in großen Repositories flüssig bleibt und nicht bei jedem Tastenanschlag neu lädt.

Erweiterte Filter

Über das Filter-Symbol (line.3.horizontal.decrease.circle) neben dem Suchfeld öffnest du zusätzliche Kriterien, die alle gemeinsam (UND-verknüpft) angewendet werden:

KriteriumBedeutung
AutorName oder E-Mail-Adresse (Teilstring)
SHACommit-Hash-Präfix — findet auch mehrdeutige Kurz-SHAs
Von / BisZeitraum mit Datum und Uhrzeit

Solange ein Suchkriterium aktiv ist, zeigt die Titelzeile die Anzahl der Treffer. Über das ×-Symbol im Suchfeld werden alle Kriterien zurückgesetzt und die vollständige Historie wieder angezeigt.

Branches und Tags

Die Seitenleiste zeigt alle lokalen Branches, Remote-Branches (gruppiert nach Remote-Namen) und Tags.

  • Der aktuelle Branch ist mit einem blau ausgefüllten Pfeil-Symbol markiert und fett geschrieben.
  • Ein Klick auf einen Branch oder Tag springt direkt zum zugehörigen Commit in der Liste — die Liste scrollt automatisch dorthin, und der Diff des Commits wird unten geladen.
  • Ein Rechtsklick bietet „Branch-Namen kopieren" bzw. „Tag-Namen kopieren" an.
  • Ein Rechtsklick auf einen lokalen, nicht aktuellen Branch bietet zusätzlich „Zu Branch wechseln" an (git checkout). Gibt es unkommittierte Änderungen, zeigt ein Warndialog, dass sie beim Wechsel verworfen werden — erst nach Bestätigung wird tatsächlich gewechselt.
  • Ein Rechtsklick auf einen Remote-Branch bietet „Lokalen Branch erstellen und auschecken" an (git checkout -b <name> <remote>). Dabei entsteht ein neuer lokaler Branch mit demselben Namen, der den Remote-Branch trackt. Auch hier gilt der Warndialog bei unkommittierten Änderungen.
  • Ein Rechtsklick auf einen lokalen, nicht aktuellen Branch bietet außerdem „Branch löschen" an — rein lokal (git branch -d bzw. bei nicht gemergten Branches nach Bestätigung -D), Remote-Branches sind davon nie betroffen. Nach einer Bestätigungsabfrage wird geprüft, ob der Branch vollständig gemergt ist: ist er es, genügt eine einfache Bestätigung; ist er es nicht, warnt ein zusätzlicher Dialog, dass dabei Commits verloren gehen können, die auf keinem anderen Branch vorhanden sind. Der aktuelle Branch sowie der letzte verbleibende lokale Branch lassen sich nicht löschen — mindestens einer bleibt immer erhalten.
Tipp: Nutze den Klick auf Branches und Tags, um schnell zwischen verschiedenen Entwicklungsständen zu navigieren, ohne scrollen zu müssen.

Mit dem Server synchronisieren

Oberhalb der Commit-Liste zeigt die Sync-Leiste den Stand gegenüber dem Server und bietet zwei Aktionen an.

  • „Vom Server prüfen" — führt git fetch aus und aktualisiert damit nur den bekannten Server-Stand (Ahead/Behind-Zahlen, Remote-Branches). Die lokalen Dateien bleiben unverändert.
  • „Aktualisieren" — übernimmt neue Server-Commits per Fast-Forward (git merge --ff-only). Das ist unkritisch, solange keine lokalen Commits oder Änderungen vom Server abweichen.

Schlägt der Fast-Forward fehl — z.B. weil es lokale, noch nicht gepushte Commits gibt oder weil unkommittierte Änderungen mit dem Server-Stand kollidieren — erscheint ein Warndialog:

„Fast-Forward nicht möglich"
Lokale Commits oder Änderungen weichen vom Server ab. Bestätigst du mit „Lokalen Stand verwerfen und synchronisieren", wird der lokale Stand hart auf den Server-Stand zurückgesetzt (git reset --hard) — sowohl unkommittierte Änderungen als auch lokale, nicht gepushte Commits gehen dabei verloren. Mit „Abbrechen" bleibt alles unverändert.

Git-Client ist als reiner Lese-/Betrachtungs-Client gedacht — dieser Hard-Reset ist die einzige bewusste Ausnahme: „Aktualisieren" soll immer zuverlässig den aktuellen Server-Stand herstellen, ohne dass du Konflikte manuell in einer Shell auflösen musst.

Fehler „index.lock: File exists"

Meldet Git neben „Vom Server prüfen" einen Fehler wie Unable to create '…/.git/index.lock': File exists, hat ein anderer Git-Prozess das Repository gerade gesperrt oder eine Sperrdatei ist nach einem Abbruch zurückgeblieben. In diesem Fall erscheint neben der Meldung der Button „Sperre aufheben".

Der Button löscht .git/index.lock und lädt das Repository neu — aber nur, wenn die Datei von keinem laufenden Prozess mehr geöffnet ist. Läuft noch ein Git-Befehl, zeigt die App stattdessen einen Hinweis, kurz zu warten und es erneut zu versuchen.

Diff ansehen

Sobald ein Commit ausgewählt ist, erscheint im unteren Bereich der Diff — alle Dateiänderungen dieses Commits im einheitlichen Patch-Format:

  • Grün hinterlegte Zeilen wurden hinzugefügt (+).
  • Rot hinterlegte Zeilen wurden entfernt (-).
  • Jede geänderte Datei wird als eigener Abschnitt mit Dateiname und Hunk-Header dargestellt.

Der Diff-Bereich erstreckt sich über die volle Breite rechts der Seitenleiste. Der Trennbalken zwischen Commit-Liste und Diff lässt sich mit der Maus verschieben, um den Platz nach Bedarf aufzuteilen.

Ein Rechtsklick auf den Commit-Kopfbereich (Betreff, Nachricht, Autor, Datum) bietet ebenfalls „SHA kopieren" und „Commit-Nachricht kopieren" an.

Zeilennummern

Links neben jeder Patch-Zeile können die alte und neue Zeilennummer angezeigt werden — wie in Sourcetree oder GitHub. Ein- und ausschaltbar unter Einstellungen › Anzeige (Standard: eingeschaltet).

JIRA-Ticket-Verknüpfung

Enthält eine Commit-Nachricht einen Ticket-Key eines konfigurierten JIRA-Projekts (z.B. PROJ-123), wird er automatisch als klickbarer Link dargestellt und öffnet das Ticket im Browser unter <Basis-URL>/browse/<KEY-123>. Server-URL und die Liste der Projekt-Keys werden unter Einstellungen › JIRA konfiguriert; ohne Konfiguration bleiben Ticket-Keys unverlinkter Text.

Datei-Kontextmenü

Ein Rechtsklick auf eine Datei in der Dateiliste des Commit-Details bietet zusätzliche Aktionen an — „Blame anzeigen" (siehe nächster Abschnitt) und „Im Finder zeigen". Beide sind nicht verfügbar für gelöschte Dateien, da es dafür keine aktuelle Datei im Arbeitsverzeichnis gibt.

Blame-Ansicht

Die Blame-Ansicht zeigt zeilenweise, wer welche Zeile einer Datei zuletzt geändert hat — im Zustand des aktuell ausgewählten Commits.

Öffnen

Rechtsklick auf eine Datei im Commit-Detail → „Blame anzeigen" öffnet ein Fenster mit einer Zeile pro Quellcode-Zeile, je mit:

SpalteBedeutung
Kurz-SHACommit, der diese Zeile zuletzt geändert hat
AutorName des Autors dieses Commits
DatumDatum dieses Commits
InhaltDer eigentliche Zeileninhalt

Ein Klick auf eine Commit-SHA in der Blame-Ansicht springt in der Hauptliste direkt zu diesem Commit. Ein Rechtsklick auf eine Zeile bietet „SHA kopieren" an.

Statistiken

Über das Diagramm-Symbol in der Toolbar öffnet sich ein eigenes Statistik-Fenster für das aktuell geöffnete Repository. Es lässt sich unabhängig vom Hauptfenster verschieben und offen halten.

Überblick (KPI-Kacheln)

Kennzahlen sind in drei umrahmte, thematische Gruppen gegliedert:

GruppeEnthält
UmfangCommits gesamt, Autoren, Branches, Tags
Zeit & FrequenzAktiver Zeitraum, Ø Commits/Woche, erster/letzter Commit, Ø Tage pro Commit, längste tägliche Commit-Streak
TeamBus Factor (minimale Autorenzahl für ≥ 80 % aller Commits), aktivster Monat, aktivster Wochentag

Commits pro Autor

Ein Balkendiagramm zeigt die Commit-Anzahl je Autor, absteigend sortiert, mit Prozentanteil an der Gesamthistorie. Autoren werden anhand ihrer E-Mail-Adresse zusammengefasst — dieselbe Person erscheint damit unabhängig von Schreibweise des Namens nur als ein Balken.

Aktivität über Zeit

Ein Flächen-/Liniendiagramm zeigt die Anzahl der Commits pro Monat über die gesamte Repository-Historie.

Commit-Rhythmus

Zwei weitere Diagramme zeigen die Verteilung der Commits nach Wochentag (Mo–So) und nach Tageszeit (0–23 Uhr) — hilfreich, um typische Arbeitszeiten im Projekt zu erkennen.

Neu laden

Mit dem Neu-laden-Button (↺) in der Toolbar werden Commits, Branches und Tags vom Repository erneut gelesen. Das ist nützlich, wenn du außerhalb der App (z.B. im Terminal) neue Commits erstellt, Branches angelegt oder Merges durchgeführt hast.

Beim Neu-laden wird die Commit-Liste von Anfang an neu aufgebaut — der Lazy-Loading-Zähler wird zurückgesetzt und die erste Seite wird erneut geladen.

Automatische Erkennung neuer Commits

Git-Client beobachtet alle Repositories aus der Übersicht im Hintergrund und macht dezent auf neue Commits aufmerksam — ohne dass du „Neu laden" klicken musst und ohne dabei selbst schreibend ins Repository einzugreifen.

Wie die Erkennung funktioniert

  • Lokal: Änderungen im .git-Verzeichnis werden per FSEvents sofort erkannt (z.B. ein Commit im Terminal) — für alle Repositories in der Übersicht.
  • Remote: In einstellbarem Intervall fragt die App per git ls-remote günstig die Branch-Stände auf dem Server ab und holt nur bei Neuigkeiten per git fetch nach. Das gilt für alle Repositories mit eingerichtetem Remote: Geklonte Repositories nutzen die in der App gespeicherte URL und Zugangsdaten, über „Repository hinzufügen" eingebundene die lokale git-Konfiguration (z.B. Credential-Helper oder SSH-Agent). Fehlen gültige Zugangsdaten, bleibt die Prüfung still ohne Ergebnis.

Wo die Hinweise erscheinen

  • In der Repository-Übersicht als kleines „neu"-Badge neben dem betroffenen Eintrag.
  • Im geöffneten Repository als Hinweis-Banner oberhalb der Commit-Liste, mit einem Button zum Aktualisieren.

Ein Klick auf „Aktualisieren" lädt die Commit-Liste lokal neu (kein zusätzlicher Download) und markiert den aktuellen Stand als gesehen — der Hinweis verschwindet.

Hinweis: Aktivierung und Intervall der automatischen Erkennung lassen sich unter Einstellungen › Aktualisierung anpassen oder ganz abschalten.

Einstellungen

Die Einstellungen öffnest du über das Menü Git-Client → Einstellungen… oder mit der Tastenkombination ⌘,. Sie sind auf vier Reiter verteilt: JIRA, Commits, Anzeige und Aktualisierung.

Reiter „JIRA"

EinstellungBedeutung
Basis-URLAdresse deines JIRA-Servers, z.B. https://firma.atlassian.net.
ProjekteListe aus Projekt-Key (z.B. PROJ) und optionaler Beschreibung. Nur Ticket-Keys der hier eingetragenen Projekte werden verlinkt (siehe JIRA-Ticket-Verknüpfung).

Reiter „Commits"

EinstellungBedeutung
Commits pro Ladevorgang Wie viele Commits beim Öffnen eines Repositories (und bei jedem Nachladen) geladen werden. Standardwert: 2.000. Mindestwert: 100. Ein kleinerer Wert beschleunigt den Start, erfordert aber häufigeres Nachladen bei langen Historien.

Reiter „Anzeige"

EinstellungBedeutung

Zeilennummern im Diff anzeigenSiehe Diff ansehen. Standardwert: eingeschaltet.

Reiter „Aktualisierung"

EinstellungBedeutung
Neue Commits automatisch anzeigenSchaltet die in automatische Erkennung beschriebene Hintergrund-Beobachtung ein oder aus.
Remote-Prüf-IntervallWie oft der Server auf neue Commits geprüft wird, in Sekunden (Mindestwert 60; 0 deaktiviert nur die Remote-Prüfung, lokale Erkennung bleibt aktiv). Gilt für alle Repositories mit eingerichtetem Remote — siehe automatische Erkennung.

Änderungen speichern

Klicke auf Speichern (oder drücke ⏎), um die Einstellungen zu übernehmen und das Fenster zu schließen. Mit Abbrechen (oder Esc) werden alle Änderungen verworfen.

Wenn du das Einstellungsfenster über den roten Schließen-Button schließt und es ungespeicherte Änderungen gibt, erscheint eine Warnung. Du kannst dann entweder die Änderungen verwerfen oder zum Dialog zurückkehren.

Hinweis: Geänderte Einstellungen zur Commit-Batch-Größe gelten ab dem nächsten Öffnen oder Neu-Laden eines Repositories — laufende Ladevorgänge werden nicht unterbrochen. Erscheinungsbild und Zeilennummern wirken sofort; Änderungen an der automatischen Erkennung gelten ab dem nächsten Start der Hintergrund-Beobachtung.
