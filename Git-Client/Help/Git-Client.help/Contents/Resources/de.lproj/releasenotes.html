Version 1.8

Neu: Datei-Historie

  • Rechtsklick auf eine Datei in der Dateiliste des Commit-Details → „Historie anzeigen": zeigt alle Commits, die diese Datei geändert haben — ausgehend vom ausgewählten Commit und auch über Umbenennungen hinweg. Rechts erscheint der Diff genau dieser Datei im gewählten Commit. Die Historie wird beim Scrollen seitenweise nachgeladen.
  • Auch aus der Blame-Ansicht erreichbar: über den Button „Historie" oder per Rechtsklick auf eine Zeile → „Datei-Historie anzeigen".
  • Doppelklick auf einen Eintrag (oder „Zum Commit springen") wählt den Commit in der Hauptliste aus.

Verbesserungen

  • Die Branch-Liste in der Seitenleiste zeigt neben dem Kurz-SHA jetzt auch das Datum der letzten Änderung (Committer-Datum der Branch-Spitze) als relative Angabe, z.B. „vor 3 Tg.". Der Tooltip nennt Datum und Uhrzeit.
  • Der Sprung zu einem Commit, der noch nicht in der Liste geladen ist (aus Blame, Datei-Historie oder per Branch-/Tag-Klick), lädt die Liste jetzt automatisch so weit nach, statt nur einen Hinweis anzuzeigen. Eine aktive Suche wird dafür zurückgesetzt. Ist ein Commit von keinem Branch oder Tag aus erreichbar, wird das ausdrücklich gemeldet.

Fehlerbehebungen

  • Der Branch-Wechsel bei unkommittierten Änderungen („Änderungen verwerfen und wechseln") konnte nach der Bestätigung stillschweigend nichts tun — weder wurde gewechselt noch eine Fehlermeldung angezeigt. Der Wechsel wird jetzt zuverlässig ausgeführt.

Version 1.7

Neu: Remote im Browser öffnen

Ein neuer Toolbar-Button (Safari-Symbol) im geöffneten Repository öffnet die Webseite des Remotes (origin) im Standardbrowser — z.B. die GitHub- oder GitLab-Seite des Projekts. Aus SSH-Adressen wie git@github.com:user/repo.git wird dafür automatisch die passende Web-Adresse gebildet. Ohne konfigurierten Remote ist der Button deaktiviert.

Verbessert: Automatische Server-Prüfung auch für hinzugefügte Repositories

Die periodische Remote-Prüfung der automatischen Erkennung läuft jetzt für alle Repositories mit eingerichtetem Remote — nicht mehr nur für geklonte. Über „Repository hinzufügen" eingebundene Repositories nutzen dafür die lokale git-Konfiguration (z.B. Credential-Helper oder SSH-Agent).

Neu: Favoriten (angepinnte Repositories)

Per Rechtsklick lässt sich ein Repository mit „Als Favorit anpinnen" oben in der Übersicht fixieren. Favoriten erscheinen alphabetisch sortiert in einem eigenen Abschnitt „Favoriten", bleiben aber zusätzlich an ihrem Platz im Ordnerbaum (dort mit Pin-Symbol). In der Befehlspalette (⌘K) stehen angepinnte Repositories ganz oben.

Fehlerbehebungen

  • Die Fehlermeldung „Unable to create '…/.git/index.lock': File exists" trat auf, wenn die Hintergrund-Aktualisierung (git status) gleichzeitig mit einer anderen Git-Aktion lief — behoben: reine Lesebefehle legen keine Sperrdatei mehr an (GIT_OPTIONAL_LOCKS=0).
  • Bleibt eine Sperrdatei trotzdem verwaist zurück (z.B. nach einem abgebrochenen Git-Prozess), erscheint neben der Fehlermeldung der Button „Sperre aufheben". Er löscht die Datei nur, wenn sie von keinem laufenden Prozess mehr verwendet wird.

Version 1.6

Neu: Lokalen Branch aus Remote-Branch erstellen und auschecken

Ein Rechtsklick auf einen Remote-Branch in der Seitenleiste bietet jetzt „Lokalen Branch erstellen und auschecken" an. Dabei entsteht ein neuer lokaler Branch mit demselben Namen, der den Remote-Branch trackt, und es wird direkt dorthin gewechselt.

Neu: Lokale Branches löschen

Ein lokaler, nicht aktuell ausgecheckter Branch lässt sich per Rechtsklick in der Seitenleiste löschen („Branch löschen") — rein lokal, Remote-Branches bleiben davon immer unberührt. Ist der Branch bereits vollständig gemergt, genügt eine einfache Bestätigung; andernfalls warnt ein zusätzlicher Dialog, dass dabei Commits verloren gehen können. Mindestens ein lokaler Branch bleibt immer erhalten.

Version 1.5

Neu: Branch wechseln

Ein lokaler, nicht aktuell ausgecheckter Branch lässt sich per Rechtsklick in der Seitenleiste direkt wechseln („Zu Branch wechseln"). Gibt es unkommittierte Änderungen, zeigt ein Warndialog, dass sie beim Wechsel verworfen werden — erst nach Bestätigung wird tatsächlich gewechselt.

Neu: "Im Terminal öffnen"

Ein Repository lässt sich jetzt per Kontextmenü (Bookmark-Browser) oder Toolbar-Button (geöffnetes Repository) direkt in der Terminal-App öffnen.

Neu: "Verwerfen & synchronisieren" beim Aktualisieren

„Aktualisieren" versucht weiterhin zuerst einen Fast-Forward. Weichen lokale Commits oder Änderungen vom Server-Stand ab und schlägt der Fast-Forward deshalb fehl, bietet ein Warndialog jetzt an, den lokalen Stand zu verwerfen und hart auf den Server-Stand zurückzusetzen — statt nur einen Fehler anzuzeigen.

Fehlerbehebungen

  • Eine länger laufende Git-Operation (z.B. Fetch) blockierte für ihre gesamte Dauer alle anderen Git-Befehle in der App — behoben.
  • Beim Aktualisieren großer Repositories erschien teils die Fehlermeldung, dass .git/index.lock bereits existiere — behoben (Rückkopplungsschleife zwischen der Hintergrund-Beobachtung und der Status-Abfrage).
  • Git-Befehle, die externe, per Homebrew installierte Helfer benötigen (z.B. git-lfs bei Repositories mit Git LFS), schlugen in der gebauten App mit „command not found" fehl, obwohl sie im Terminal funktionierten — behoben.

Version 1.4

Neu: Befehlspalette (⌘K)

Eine Spotlight-artige Befehlspalette durchsucht auf Tastendruck alle Repository-Bookmarks sowie — sobald ein Repository geöffnet ist — dessen bereits geladene Branches, Tags und Commits. Mit den Pfeiltasten navigieren, mit ⏎ öffnen/ansteuern, mit Esc schließen.

Neu: Kopieren-Affordanzen

SHA, Branch-/Tag-Name und Commit-Nachricht lassen sich jetzt per Rechtsklick-Kontextmenü in die Zwischenablage kopieren — in der Commit-Liste, im Diff-Kopfbereich, an Branch- und Tag-Einträgen sowie in der Blame-Ansicht.

Neu: "Im Finder zeigen" für Dateien

Ein Rechtsklick auf eine Datei in der Diff-Dateiliste zeigt sie direkt im Finder — analog zur bereits vorhandenen Aktion auf Repository-Ebene.

Fehlerbehebungen

  • Einstellungen (u.a. die JIRA-Konfiguration) konnten beim Ausführen der Testsuite versehentlich überschrieben oder gelöscht werden und gingen dadurch verloren — behoben.

Version 1.3

Neu: Repository-Statuszeile in der Übersichtsliste

Jeder Eintrag in der Repository-Übersicht zeigt jetzt direkt den aktuellen Branch, ob Commits gegenüber dem Remote ahead/behind sind, ob es unkommittete Änderungen gibt sowie das Datum des letzten Commits — ganz ohne das Repository zu öffnen.

Neu: Repository-Statistiken in einem eigenen Fenster

Über die Toolbar lässt sich pro Repository ein eigenes Statistik-Fenster öffnen. Es zeigt Kennzahlen wie Bus-Faktor, aktivsten Monat/Wochentag und durchschnittlichen Commit-Abstand als KPI-Kacheln — zur besseren Orientierung in thematische, umrahmte Gruppen gegliedert — sowie ein Autoren-Chart und Verteilungen nach Monat, Wochentag und Uhrzeit.

Fehlerbehebungen

  • Der Wechsel des Erscheinungsbilds (Hell/Dunkel/Wie System) greift jetzt sofort und zuverlässig — vorher blieb die Anzeige teils bis zu einem Fokuswechsel im alten Zustand.
  • Autoren-Chart in den Statistiken: Autoren werden jetzt korrekt nach E-Mail-Adresse statt nach Name gruppiert, wodurch dieselbe Person nicht mehr mehrfach als eigener Balken erschien; Sortierung und Balkendarstellung wurden ebenfalls korrigiert.

Version 1.2

Neu: Commit-Suche & Filter

Die Commit-Liste lässt sich jetzt durchsuchen und filtern — nach Nachricht, Autor oder Zeitraum (Von/Bis mit Uhrzeit). Die Eingabe wird entprellt, sodass die Suche auch in großen Repositories flüssig bleibt.

Neu: Erweiterte Dateiliste pro Commit

Zu jedem Commit zeigt die Dateiliste nun den Änderungstyp (hinzugefügt, geändert, gelöscht) als Symbol sowie die +/−-Zeilenstatistik. Ein Klick auf eine Datei springt direkt zum Diff.

Neu: Ahead/Behind-Anzeige pro Branch

In der Seitenleiste zeigen Badges an, wie viele Commits ein Branch vor bzw. hinter seinem Remote liegt.

Neu: JIRA-Verknüpfung

Ticket-Keys wie PROJ-123 in Commit-Nachrichten werden erkannt und als klickbare Links dargestellt. Server-URL und Projekt-Keys werden unter Einstellungen › JIRA konfiguriert.

Neu: Blame-Ansicht

Per Rechtsklick auf eine Datei im Commit-Detail lässt sich anzeigen, wer welche Zeile zuletzt geändert hat — inklusive Commit und Autor je Zeile.

Neu: Automatische Erkennung neuer Commits

Git-Client beobachtet Repositories im Hintergrund (FSEvents lokal) und gleicht per git fetch periodisch den Server-Stand ab. Neue Commits erscheinen als Badge in der Übersicht und als Hinweis-Banner im geöffneten Repository. Der Remote-Abgleich läuft nur für Repositories, die über „Klonen" hinzugefügt wurden (gespeicherte Remote-URL); über „Repository hinzufügen" eingebundene Repositories erhalten nur die lokale Erkennung. Intervall und Aktivierung unter Einstellungen › Aktualisierung.

Neu: Zeilennummern im Diff

Der Diff-Patch kann links neben jeder Zeile die alte und neue Zeilennummer anzeigen — wie in Sourcetree oder GitHub. Umschaltbar unter Einstellungen › Anzeige.

Neu: Erscheinungsbild wählbar

Das Design lässt sich auf Hell, Dunkel oder Wie System einstellen (Einstellungen › Anzeige). Die Änderung greift sofort ohne Neustart.

Fehlerbehebungen

  • Absturz (EXC_BAD_ACCESS) im Hintergrund-Watcher behoben: der FSEvent-Callback hat den CFArray-Pointer falsch interpretiert und dabei in ungültigen Speicher gelesen.

Sonstiges

  • Über-Dialog um Copyright und Credits erweitert.
  • Git-Client bleibt ein reiner Lese-Client: keinerlei schreibende Git-Operationen.

Version 1.1

Neu: Lazy Loading der Commit-Liste

Große Repositories werden jetzt deutlich schneller geöffnet. Beim Start lädt die App nur die neuesten 2.000 Commits (Standardwert). Sobald du ans Ende der Liste scrollst, werden automatisch weitere Commits nachgeladen — ohne manuellen Eingriff, so lange bis die vollständige Historie angezeigt wird.

Neu: Einstellungen (⌘,)

Im neuen Einstellungsdialog lässt sich die Anzahl der Commits pro Ladevorgang anpassen. Änderungen werden erst mit Speichern übernommen; mit Abbrechen (Esc) werden sie verworfen. Wird das Fenster über den roten Schließen-Button geschlossen und es gibt ungespeicherte Änderungen, erscheint eine Warnung.

Neu: Repository klonen

Repositories können jetzt direkt aus der App heraus über eine HTTPS-URL geklont werden. Für private Repositories lassen sich Benutzername und Passwort/Token angeben. Die Zugangsdaten werden sicher im macOS Keychain gespeichert — nie in einer Datei.

Fehlerbehebungen

  • Commit-Graph ohne Lücken zwischen den Zeilen.
  • Diff-Panel füllt jetzt die volle Breite rechts der Seitenleiste aus.
  • Beim Öffnen eines Repositories wird eine sinnvolle Fenster-Mindestbreite gesetzt.
  • Platzhalter-Ansichten (leere Zustände) füllen die volle Breite aus.

Sonstiges

  • Unit-Test-Abdeckung auf 83 % der nicht-View-Dateien erhöht.
  • Hilfe um Speicherpfade, Lazy Loading, Einstellungen und Sicherheitskonzept erweitert.

Version 1.0

Erste Veröffentlichung. Enthält:

  • Bookmark-Browser mit Ordnern, Drag & Drop und Kontextmenü.
  • Commit-Graph mit farbigen Lanes, Ref-Badges (Branch, Tag, HEAD).
  • Diff-Ansicht im einheitlichen Patch-Format.
  • Branch- und Tag-Navigation mit Sprung zum zugehörigen Commit.
  • Neu-laden-Funktion (↺) für externe Git-Operationen.
